# 05 — قواعد التبرع والأهلية

## ما يفعله العميل / Firestore اليوم

| البند | الوضع |
|-------|--------|
| `eligible_until` على مستند المتبرع | حقل في Firestore — يُستخدم ضمنياً في البحث |
| تسجيل تبرع في المركز | غير واضح في UI القديم — قد يكون يدوياً |
| فلترة المتبرعين في البحث | جزء في العميل (`isShown`) + Firestore |

## ما يوفّره الباكإند اليوم

| Endpoint | السلوك |
|----------|--------|
| `GET /donor-search` | يستبعد `eligibleUntil` المستقبلي و `isShown=false` (**موجود**) |
| `POST /centers/me/donations` | يسجّل `Donation` (**موجود**) |
| توثيق صريح | **`eligibleUntil` لا يُحدَّث تلقائياً** عند التبرع |

---

## منطق يُنقل إلى الباكإند — **مطلوب (P2)**

### 1. تحديث `eligibleUntil` بعد التبرع

**قاعدة أعمال مقترحة (تؤكد مع الفريق الطبي):**

```text
عند POST /centers/me/donations ناجح:
  donor.eligibleUntil = now + 90 days   (مثال)
  اختياري: isShown = false خلال فترة الأهلية
```

| حقل | مصدر |
|-----|------|
| مدة الحظر | `app-config` → `donation_cooldown_days` (افتراضي 90) |
| تطبيق | داخل service بعد إنشاء `Donation` — transaction |

**معايير قبول:**

- [ ] `GET /donors/me` يعكس `eligibleUntil` فوراً بعد التبرع.
- [ ] `GET /donor-search` لا يعيد المتبرع حتى انتهاء المدة.
- [ ] توثيق في `centers-and-inventory.md`.

### 2. إشعار المتبرع بعد تسجيل التبرع — **اختياري (P3)**

| مقترح | |
|--------|--|
| بعد `POST /centers/me/donations` | FCM للمتبرع: "شكراً لتبرعك" |

يستخدم نفس بنية `/auth/device` — لا إرسال من العميل.

### 3. التحقق من هوية المتبرع عند التبرع — **جزئي**

المركز يمرّر `donorId` (رقم مستخدم API).

| مطلوب | |
|--------|--|
| التحقق أن `donorId` موجود و role=DONOR | |
| رفض 404/400 إن غير موجود | |
| اختياري: مسح QR يربط بـ `userId` لاحقاً |

# 02 — البحث والتحليلات

## ما يفعله العميل اليوم

| الموقع | السلوك |
|--------|--------|
| `search_repo_impl.dart` | استعلام Firestore: `donors` حسب `state` (واختياري district للمراكز) |
| `search_cubit.dart` | فلترة **محلية** حسب `district` بعد جلب كل متبرعي المحافظة |
| `search_cubit.dart` | كتابة `search_logs`: state, district, bloodType, date, donorsCount, FCM token, userType |
| `lib/domain/entities/blood_types.dart` | منطق فصائل متوافقة (عرض UI) — يبقى جزء منه في العميل |

## ما يوفّره الباكإند اليوم (**موجود**)

| Endpoint | يغطي |
|----------|--------|
| `GET /donor-search` | بحث جغرافي: `bloodType`, `lat`, `lon`, `radiusKm?`, `stateId?` — يستبعد `eligibleUntil` و `isShown=false` |
| `GET /donor-search/manual` | `bloodType`, `stateId?`, `districtId?` + pagination |
| `GET /centers` | قائمة مراكز |
| `GET /centers/:id/stock` | مخزون |
| `GET /admin/stats` | `totalSearches` (إحصاء **عام** — مصدره يجب أن يكون السيرفر) |

**المطلوب من العميل:** استدعاء API فقط — لا فلترة district بعد الجلب إن كان `districtId` يُمرَّر للـ manual endpoint.

## فجوات / مطلوب من الباكإند

### 1. تسجيل عملية البحث (`search_logs`) — **مطلوب (P1)**

**العميل كان يكتب:**

```text
collection: search_logs
  state, district, bloodType, date, donorsCount, token, userType
```

**مقترح API (اختر أحد النمطين):**

**أ) تسجيل ضمني (مفضل):**

- عند كل `GET /donor-search` أو `/donor-search/manual` ناجح: زيادة عداد + إدراج سجل تحليلات (بدون استدعاء منفصل من العميل).

**ب) endpoint صريح:**

```http
POST /analytics/search
Authorization: Bearer <optional>
x-device-id: <uuid>

{
  "bloodType": "O+",
  "stateId": 100,
  "districtId": 1001,
  "lat": 15.37,
  "lon": 44.19,
  "mode": "geo" | "manual",
  "resultCount": 12
}
```

**201** — بدون body حساس. Throttle: مثلاً 30/دقيقة per device.

**ربط مع Admin:**

- `GET /admin/stats` → `totalSearches` يجب أن يعكس هذا المصدر وليس Firestore.

### 2. فصائل الدم المتوافقة — **اختياري (P2)**

العميل يوسّع نوع دم واحد إلى عدة أنواع للعرض.

| خيار | وصف |
|------|-----|
| A | يبقى في العميل — عدة طلبات API بأنواع متوافقة |
| B | `GET /donor-search?bloodType=O+&includeCompatible=true` — السيرفر يوسّع المجموعة |

**توصية:** B يقلل الطلبات ويوحّد القواعد طبياً على السيرفر.

### 3. فلترة المراكز حسب الموقع — **جزئي**

العميل يفلتر مراكز بـ `state` + `district` نصاً.

| المطلوب | |
|---------|--|
| توثيق query لـ `GET /centers` | `stateId?`, `districtId?`, `lat?`, `lon?`, `radiusKm?` إن وُجدت |
| أو endpoint | `GET /centers/nearby` مشابه لـ donor-search |

## ما لا يجب على الباكإند (يبقى في العميل)

| البند | السبب |
|-------|--------|
| كاش `locations` في Drift | تحسين offline — بيانات من `GET /locations` |
| عرض المسافة `distance_km` | السيرفر يحسبها في `/donor-search` |
| ترتيب UI للنتائج | عرض فقط |

## معايير قبول

- [ ] لا collection `search_logs` في Firebase.
- [ ] `totalSearches` في `/admin/stats` يزيد مع عمليات البحث الفعلية.
- [ ] البحث بالمديرية يعمل عبر `districtId` في API دون جلب محافظة كاملة.

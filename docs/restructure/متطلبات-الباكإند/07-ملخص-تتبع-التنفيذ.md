# 07 — ملخص تتبع التنفيذ (باكإند)

جدول واحد لتنسيق الفريقين. حدّث الحالة عند التنفيذ.

| ID | الموضوع | الحالة API | أولوية | ملاحظة |
|----|---------|------------|--------|--------|
| BE-01 | FCM إرسال من السيرفر فقط | جزئي (blood-requests) | P0 | تدوير Server Key |
| BE-02 | `POST /auth/device` | موجود | P0 | العميل يلتزم |
| BE-03 | إزالة broadcast/topic من العميل | — | P0 | قرار A/B في 01 |
| BE-04 | `app-config` سلايدر + فعاليات | جزئي | P1 | seed من Firestore |
| BE-05 | `min_app_version` + رسائل تحديث | جزئي | P1 | حقول اختيارية |
| BE-06 | تسجيل `search_logs` / `totalSearches` | جزئي (stats فقط) | P1 | تسجيل ضمني أو POST |
| BE-07 | `GET /centers` بفلتر موقع | تحقق | P2 | توثيق query |
| BE-08 | `includeCompatible` في بحث الدم | غير موجود | P2 | اختياري |
| BE-09 | `eligibleUntil` عند التبرع | غير موجود | P2 | قاعدة + app-config |
| BE-10 | حد تسجيل يومي | throttle عام فقط | P2 | بديل users_per_day |
| BE-11 | إشعار شكر بعد تبرع | غير موجود | P3 | FCM |
| BE-12 | `POST /admin/notifications/send` | غير موجود | P3 | بديل إرسال يدوي |

## حالة العميل المرتبطة

| عند اكتمال BE-ID | الموبايل |
|------------------|----------|
| BE-01, BE-03, BE-06 | حذف 06 + 01 من الكود |
| BE-04, BE-05 | مرحلة 4 restructure |
| BE-09 | تحديث UI مركز + رسالة للمتبرع |

## قالب طلب تغيير API

عند إضافة endpoint جديد، حدّث:

1. `docs/backend_guide/api/<module>.md`
2. صف في هذا الجدول
3. `docs/restructure/` للمرحلة المتأثرة

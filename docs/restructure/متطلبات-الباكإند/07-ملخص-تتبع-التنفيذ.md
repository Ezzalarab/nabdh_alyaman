# 07 — ملخص تتبع التنفيذ (باكإند)

جدول واحد لتنسيق الفريقين. حدّث الحالة عند التنفيذ.

> **مزامنة مع `docs/backend_docs/implementation-status.md`:** إذا زعم ملف الحالة أن ميزة منجزة في السيرفر بينما العميل لا يراها، فالحقيقة هي **نسخة السيرفر المنشورة** أو فرق بين الريبوين — سجّل التاريخ/البيئة.

| ID | الموضوع | الحالة API | أولوية | ملاحظة |
|----|---------|------------|--------|--------|
| BE-01 | FCM إرسال من السيرفر فقط | جزئي (blood-requests) | P0 | تدوير Server Key في العميل إن سُرّب |
| BE-02 | `POST /auth/device` | موجود ([دليل API](../../backend_guide/api/authentication.md)) | P0 | العميل يلتزم |
| BE-03 | إزالة broadcast/topic من العميل | — | P0 | قرار A/B في 01 |
| BE-04 | `app-config` سلايدر + فعاليات | جزئي | P1 | seed من Firestore؛ راجع curl على الإنتاج |
| BE-05 | `min_app_version` + رسائل تحديث | جزئي | P1 | حقول اختيارية |
| BE-06 | تسجيل `search_logs` / `totalSearches` | جزئي (stats في [admin](../../backend_guide/api/admin.md)) | P1 | تسجيل ضمني أو POST |
| BE-07 | `GET /centers` بفلتر موقع | تحقق | P2 | توثيق query في donors-and-search / centers |
| BE-08 | `includeCompatible` في بحث الدم | راجع [implementation-status](../../backend_docs/implementation-status.md)؛ العقد في [donors-and-search](../../backend_guide/api/donors-and-search.md) | P2 | اختياري في العميل |
| BE-09 | `eligibleUntil` عند التبرع | **موثّق** في [centers-and-inventory](../../backend_guide/api/centers-and-inventory.md) + [implementation-status](../../backend_docs/implementation-status.md) | P2 | المهمة المتبقية: **تأكيد الإنتاج** + عدم تكرار المنطق في العميل (كان سابقاً تعارضاً في متطلبات-05 — مُصلَح) |
| BE-10 | حد تسجيل يومي | راجع AppConfig في السيرفر | P2 | بديل `users_per_day` |
| BE-11 | إشعار شكر بعد تبرع | راجع implementation-status | P3 | FCM |
| BE-12 | `POST /admin/notifications/send` | **موثَّق** ([admin.md](../../backend_guide/api/admin.md))؛ التحقق من الإنتاج | P3 | ADMIN فقط — خارج تطبيق المتبرع |

## حالة العميل المرتبطة

| عند اكتمال BE-ID | الموبايل |
|------------------|----------|
| BE-01, BE-03, BE-06 | حذف 06 + 01 من الكود |
| BE-04, BE-05 | مرحلة 4 restructure |
| BE-09 | تحديث UI مركز + رسالة للمتبرع |

## لقطات تحقق من الخادم (توثيق)

عند تنفيذ DTO أو UI تعتمد على شكل حقول حقيقية (خصوصاً `GET /app-config` وقيود الإصدارات)، سجّل **تاريخ التحقّق** والبيئة حتى لا يبقى «جزئي» بدون مرجع.

| البند | تاريخ التحقق | البيئة (إنتاج / staging / محلي + commit أو tag) | أمر أو ملاحظة |
|-------|----------------|---------------------------------------------------|----------------|
| حقول السلايدر والفعاليات في `app-config` | — | — | مثلاً `curl -sS "https://nabdh.telqaia.com/api/v1/app-config"` ثم ملاحظات بالحقول المعتمدة للعميل |
| `min_app_version` ورسالة التحديث | — | — | |
| `eligibleUntil` / تبرّع مركز بعد التحديث المنشور | — | — | |
| بحث المراكز أو فلاتر مشكوك فيها (BE-07) | — | — | |

## قالب طلب تغيير API

عند إضافة endpoint جديد، حدّث:

1. `docs/backend_guide/api/<module>.md`
2. صف في هذا الجدول وحدّث `docs/backend_docs/implementation-status.md` عند الحاجة
3. `docs/restructure/` للمرحلة المتأثرة في الموبايل

# 10 — طلبات الدم (استغاثة)

## الهدف

توثيق وتنفيذ ميزة **طلبات الدم** عبر API — غير موجودة حالياً في التطبيق (كانت إشعارات يدوية فقط).

## الوضع الحالي

- لا UI لـ blood requests.
- إرسال إشعارات يدوي من `home_page` / `send_notfication_impl` — **يُحذف**.
- FCM سيستقبل `BLOOD_REQUEST` (انظر 09).

## API المرجعي

[`docs/backend_guide/api/blood-requests-and-notifications.md`](../../backend_guide/api/blood-requests-and-notifications.md)

| Method | Path | Auth | ملاحظات |
|--------|------|------|---------|
| POST | `/blood-requests` | JWT | 5/دقيقة throttle |
| GET | `/blood-requests` | لا | قائمة عامة |
| GET | `/blood-requests/my` | JWT | طلباتي |
| GET | `/blood-requests/:id` | لا | تفاصيل |
| PATCH | `/blood-requests/:id/status` | JWT owner | `FULFILLED`, `CANCELLED` |

### إنشاء طلب

```json
{
  "bloodType": "O+",
  "locationId": 1,
  "hospitalName": "...",
  "lat": 15.36,
  "lon": 44.20,
  "patientName": "...",
  "unitsNeeded": 2,
  "urgency": "HIGH"
}
```

- حالة ابتدائية: `OPEN`
- `expiresAt`: +24h تلقائياً
- **429** إن وُجد طلب OPEN آخر لنفس المستخدم

## BloodRequestBloc

### Events

- `BloodRequestCreateSubmitted`
- `BloodRequestListLoadRequested` (عام أو my)
- `BloodRequestDetailLoadRequested` (id)
- `BloodRequestStatusUpdateSubmitted` (id, status)

### States

- `BloodRequestLoading`, `BloodRequestListLoaded`, `BloodRequestDetailLoaded`, `BloodRequestSuccess`, `BloodRequestFailure`

## التكامل

| مصدر | سلوك |
|------|------|
| FCM `BLOOD_REQUEST` | `notification_router` → `BloodRequestDetailPage` |
| Home | زر "طلب استغاثة" للمستخدم المسجّل |
| Search | عرض طلبات قريبة من `GET /blood-requests` (فلترة client-side بالموقع) |

## معايير قبول

- [ ] إنشاء طلب OPEN ينجح.
- [ ] محاولة ثانية OPEN → رسالة 429 واضحة.
- [ ] إلغاء/إتمام الطلب من المالك.
- [ ] فتح إشعار FCM يعرض التفاصيل.
- [ ] لا إرسال FCM من العميل.

## مخاطر

| الخطر | التخفيف |
|-------|---------|
| إساءة إنشاء طلبات | احترام throttle + تأكيد UI |
| موقع خاطئ | التحقق من lat/lon قبل الإرسال |

## ترتيب التنفيذ

يُنفَّذ **بعد** اكتمال المراحل 0–4 (بما فيها 09 — توجيه FCM لـ `BLOOD_REQUEST`).

**اعتماد:** يتطلب `AuthBloc` (1) ويفضّل اكتمال البحث/الموقع (2) لعرض الطلبات القريبة على الخريطة.

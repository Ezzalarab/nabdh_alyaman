# 03 — التهيئة DI والمنصات

## الهدف

تنظيم GetIt لطبقات data/domain/presentation الجديدة، وتهيئة التطبيق لـ Android الآن مع قابلية iOS/Web.

## الوضع الحالي

- `lib/di.dart` — تسجيل repositories Firebase + cubits.
- `main.dart` — `Firebase.initializeApp`, `MultiBlocProvider` مع cubits، استدعاء `gi<SignInCubit>()` قبل `initSignIn()` (خطأ ترتيب محتمل).
- `initSignIn()` / `initSignUp()` — تسجيل متأخر من الصفحات.

## هيكل مجلدات مستهدف (تدريجي)

```text
lib/
  core/           # network, config, error, utils
  data/
    datasources/
      remote/     # auth_remote_ds.dart, donor_remote_ds.dart, ...
      local/      # session, prefs, drift
    models/       # DTOs + fromJson/toJson
    repositories/ # *RepositoryImpl
  domain/
    entities/
    repositories/ # abstract
    usecases/
  presentation/
    blocs/        # auth/, search/, profile/, ...
    pages/
    widgets/
```

## حزم مقترحة (مرحلة 0 — `pubspec.yaml`)

| حزمة | الغرض |
|------|--------|
| `dio` | HTTP (يبقى `http` مؤقتاً لـ FCM القديم حتى 09) |
| `flutter_secure_storage` | tokens |
| `shared_preferences` | prefs + device_id |
| `drift`, `drift_flutter`, `sqlite3_flutter_libs` | locations |
| `equatable` | Bloc states/events |
| `intl` | تواريخ UTC → محلي |

`dev_dependencies`: `drift_dev`, `build_runner`, `bloc_test` (من مرحلة 1).

## تسجيل GetIt (مقترح)

```dart
// ترتيب التسجيل
1. AppConfig, DeviceIdService
2. AppDatabase (Drift)
3. Local data sources
4. ApiClient (Dio)
5. Remote data sources
6. Repositories
7. Use cases
8. Blocs (factory للشاشات، lazySingleton للعالمية)
```

### Blocs عالمية vs factory

| Bloc | نمط | سبب |
|------|-----|-----|
| AuthBloc | lazySingleton | جلسة على مستوى التطبيق |
| AppConfigBloc | lazySingleton | بيانات الصفحة الرئيسية |
| SearchBloc | lazySingleton | مشترك بين search/map |
| ProfileBloc | factory | شاشة إعدادات |
| CenterBloc | factory | لوحة المركز |

## `main.dart` — تهيئة مستهدفة

```text
1. WidgetsFlutterBinding.ensureInitialized()
2. await configureDependencies()
3. Firebase.initializeApp()              # FCM فقط
4. runApp(MyApp)                         # AuthBloc يبدأ AuthCheckRequested
5. بعد أول frame: FCM token → POST /auth/device (بدون JWT إن لم يكن login)
6. MultiBlocProvider: AuthBloc (+ لاحقاً AppConfigBloc, SearchBloc, ...)
7. MaterialApp — redirect حسب AuthState + role
```

**إصلاح خطأ حالي:** لا تستدعِ `gi<SignInCubit>()` في `main` قبل `initSignIn()` — سجّل `AuthBloc` في `configureDependencies` من البداية.

## التوجيه حسب الدور

بعد `AuthAuthenticated`:

| `role` | الشاشة الافتراضية |
|--------|-------------------|
| `DONOR` | Home (متبرع) |
| `CENTER` | Center dashboard |

لا مسارات Admin.

## جاهزية iOS / Web

| القلق | الحل |
|-------|------|
| `dart:io` في data | `PlatformInterface` أو `kIsWeb` في presentation فقط |
| secure storage على web | تخطيط `flutter_secure_storage` web أو بديل لاحق |
| Firebase options | إعادة `flutterfire configure` عند دعم iOS |
| ملفات Drift | `drift_flutter` يدعم multi-platform |

أنشئ:

```text
lib/core/platform/
  device_info_service.dart       # abstract
  device_info_service_android.dart
  # device_info_service_ios.dart — لاحقاً
```

## الملفات — إنشاء / تعديل / حذف

| إجراء | مسار |
|-------|------|
| إعادة كتابة | `lib/di.dart` → `lib/injection.dart` (اختياري rename) |
| تعديل | `lib/main.dart` |
| إنشاء | `lib/core/platform/device_info_service.dart` |
| حذف لاحقاً | `initSignIn`, `initSignUp` — استبدال بتسجيل AuthBloc ثابت |

## معايير قبول

- [ ] التطبيق يقلع بدون استثناء GetIt.
- [ ] جميع Blocs تُحل من DI — لا `MapsCubit()` مباشرة في main.
- [ ] `--dart-define=API_BASE_URL` يغيّر السيرفر فعلياً.
- [ ] لا استيراد `cloud_firestore` / `firebase_auth` في `di.dart` الجديد.

# عميل رفيع (Thin Client) ومصدر الحقيقة

## القاعدة

بعد اكتمال الهجرة، **العميل لا يملك قواعد أعمال** إلا التحقق من الواجهة (تحقق من النماذج، أذونات المستخدم، عرض/إخفاء عناصر). **كل قرار** (من يظهر في البحث، من يستقبل إشعاراً، أهلية التبرع، حد التسجيل، تحليلات) يُنفَّذ على **السيرفر** ويُعرَّض عبر REST.

حتى اكتمال كود الـ API في التطبيق، نعتبر **العقد في `docs/backend_guide/`** هو ما «يجب أن يفعله السيرفر» — حتى لو كانت بعض السطور في الكود لا تزال Firebase.

## ما يبقى في العميل (مسموح)

| الطبقة | أمثلة |
|--------|--------|
| عرض | widgets، تنسيق، RTL، ضغط صورة قبل الرفع |
| حالة UI | Bloc states، تنقل، `package_info` |
| تخزين محلي | tokens (secure)، preferences، Drift لـ `/locations` |
| أخطاء عرض | ترجمة `statusCode` / `code` من الاستجابة |

## ما يُزال من العميل (إجباري عند الهجرة)

| المنطق القديم | البديل على السيرفر (عقد) |
|---------------|---------------------------|
| استعلام Firestore للبحث / الملف | `GET /donor-search`, `/donors/me`, … |
| فلترة مديرية بعد جلب المحافظة | `districtId` في `/donor-search/manual` |
| `search_logs` | تسجيل ضمني لرؤوس البحث أو جدول `SearchLog` |
| عدّ `users_per_day` | `AppConfig` + rate limit على `POST /auth/register` |
| إرسال FCM HTTP | `POST /blood-requests`, `/admin/notifications/send`, … |
| Firebase Phone OTP للتسجيل | `POST /auth/register` + كلمة مرور؛ OTP لنسيان كلمة المرور فقط |
| تحديث إجبارية من Firestore `updating` | `GET /app-config` → `min_app_version` |

## مصدر الحقيقة عند التعارض

1. **`docs/backend_guide/`** — العقد.
2. **`docs/backend_docs/implementation-status.md`** — ادّعاء تنفيذ؛ يُصحَّح بالتاريخ/البيئة إن خالف الإنتاج.
3. **الكود الحالي** — أثناء الهجرة فقط؛ أي تعارض مع أعلاه يُعالَج بدمج API وليس بقوة منطق في العميل.
